## Summary of PLC Connection Observations

Based on the documentation in your files, here are the key observations:

### **System Architecture Concepts**
Your system uses four core concepts:
1. **Register Mapping** – Data is shared via numbered memory slots (Holding Registers 0-13) rather than text
2. **Numeric Command Codes** – Commands are encoded as numbers (1=Get from, 2=Put on, 3=Wait for sec)
3. **State Machines** – A handshake protocol ensures Python and PLC stay synchronized
4. **Structured Packets** – The Modbus TCP library automatically packages data into binary frames

### **Communication Flow**
The handshake protocol works like this:
1. Python waits for **PLC_READY == 1** (PLC idle)
2. Python writes instruction data to registers HR[0-5]
3. Python sets **CMD_EXECUTE = 1** (triggers execution)
4. Python waits for **CMD_DONE == 1** (PLC finished)
5. Python resets **CMD_EXECUTE = 0** (both sides reset)
6. Repeat for next instruction

### **Register Map (7 write, 4 read)**
| Address | Direction | Purpose |
|---------|-----------|---------|
| HR[0-5] | Python→PLC | Instruction type, value, load number, FlightBar ID, time |
| HR[6] | Python→PLC | CMD_EXECUTE trigger |
| HR[10-13] | PLC→Python | Ready flag, Done flag, Status code, Alarm code |

### **Execution Log Output**
Each instruction line shows: `SR#001 | Get from | Value=1 | Load=1 | FB1 | T=10s`
- **SR#** = step number in sequence
- **Instruction type** = action (Get from, Put on, Wait)
- **Value** = station/tank number or wait seconds
- **Load** = batch ID (0 = empty hoist)
- **FB** = physical FlightBar ID
- **T** = accumulated timeline in seconds

### **Protocol Support**
- **Primary**: Modbus TCP (works with most PLCs)
- **Alternative**: Siemens S7 (Snap7), Allen-Bradley EtherNet/IP (PyComm3), OPC-UA (AsyncUA)
